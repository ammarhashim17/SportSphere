# ScoreSphere — Architecture & Implementation Deviations Log

This document records approved deviations and operational adaptations made during Phase 1 implementation relative to the original specification:

| ID         | Topic                          | Specified                   | Implemented                           | Rationale                                                                                                                                                                                         |
| ---------- | ------------------------------ | --------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **DEV-01** | Package Manager                | `pnpm` (SRS 9.4)            | `npm`                                 | ADR-03: Expo SDK 54 native autolinking and development builds have fewest dependency and symlink edge cases on Windows when using npm.                                                            |
| **DEV-02** | Monorepo Structure             | Monorepo (SRS 9.4)          | Single App Package                    | ADR-02: Single app layout with pure domain logic isolated in `src/core/` (zero React/RN dependencies, enforced by linting) for clean extraction into a shared package in Phase 3.                 |
| **DEV-03** | React 19 Dependency Resolution | Default npm peer resolution | `.npmrc` with `legacy-peer-deps=true` | React 19.1.0 pinned by Expo SDK 54 required legacy peer dependency resolution for compatible sub-dependencies.                                                                                    |
| **DEV-04** | Session Storage                | Expo SecureStore only       | LargeSecureStore (AES + AsyncStorage) | ADR-11 / SEC-02: SecureStore on Android has an arbitrary size limit (2048 bytes); LargeSecureStore stores the AES encryption key in SecureStore and encrypted session ciphertext in AsyncStorage. |
| **DEV-05** | Remote State Management        | TanStack Query (SRS 9.1)    | Zustand + Drizzle                     | ADR-13: No remote-only fetch endpoints exist in Phase 1; all data access goes through local SQLite + Outbox sync pipeline.                                                                        |
| **DEV-06** | Home Dashboard Wiring          | Real scoring data           | Stitch Fixture Data (`stitchHome.ts`) | ADR-15: Match fixtures match Stitch `home_dashboard` 1:1; live match data will connect in Phase 2 upon completion of the scoring engine.                                                          |
| **DEV-07** | Non-Stitch Screens             | Pending Stitch designs      | TEMP-UI Screen Suite                  | ADR-16 / LOCK-03: Auth screens, Teams, and Players management implemented using the locked design system primitives, ready for 1:1 replacement when final Stitch designs are approved.            |
